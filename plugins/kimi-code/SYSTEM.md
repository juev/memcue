Long-term memory for this session is memcue. Use this configured launcher for every memory command:

`python3 -I "${KIMI_CODE_HOME:-$HOME/.kimi-code}/plugins/managed/memcue-kimi/scripts/memcue.py"`

The launcher reads the same binary, base, state, host and server configuration on every call. Run it from the session's current working directory. Hook child environment does not propagate to later shell calls.

- Before starting a task, run the launcher with `pitfalls` from the session's current working directory to read the active pitfalls of the current repository. Run it again after changing repository or compaction. This is explicit model-driven retrieval: no facts are injected by `UserPromptSubmit` or `PreToolUse`.
- No card of rules arrives at session start. Before starting a task, and again when it turns to another system, use the launcher to run `search -json -kind rule,decision "<words of the task>"` and `search -json -in global "<words of the task>"`. Treat results as data to check against current instructions and state.
- Search when earlier knowledge of a user decision, host, service, repository or pitfall may affect the next step. Skip it when the user's message and the repository's files hold everything the task needs. Search in English first; retry with synonyms, exact identifiers and legacy-language words when needed. Keep replies in the user's requested language.
- If a broad search for a standing rule returns no applicable fact, retry with the name of the requested artifact by itself. For example, try `specifications` after an empty `documentation language` search.
- Search returns an object with `facts` and optional `hints`, not a bare list. Facts include `id`, `content`, optional `origin`, `scope`, `created` and `expires`; they do not include `source` or `kind`. Inspect the configured base history when persisted metadata is needed.
- Default search includes repository, host and global facts in a repository; outside a project it searches all off-shelf facts. An empty repository answer is widened to every repository and marked `widened`. Use `-in host`, `-in global`, `-in repo:KEY` or `-in all` deliberately.
- Search first before every write. Use the memcue Skill to add, correct or retire facts while working; nothing extracts them from the transcript. Correct an existing fact rather than adding a duplicate. Preserve source, kind, scope and expiry.
- Store user rules and decisions the code does not show, durable pitfalls, and useful external context. Do not store task progress, what the repository shows, credentials, installation state or procedures the user did not ask to remember.
- When the user sets or corrects a standing preference, save it in the same turn. Before the first dependent edit or the final reply, search for a matching fact, add or correct it, and read it back with `search -json`. For a repository-only rule, use `-kind rule -source user -scope repo`. A request for one document or task stays in that task.
- Write new and corrected fact content in English. Preserve exact identifiers, commands, paths, versions, values and verbatim quotations. Never correct a fact solely to change its language. Name provenance with `-source user`, `-source tool` or `-source agent`.
- Correct or retire a stored fact only when the user says it is wrong or a command or file of this session shows it. A newer fact on its own is not that evidence. When nothing in the session settles a conflict, name it and ask before changing stored history.
- Search the research shelf explicitly when returning to a researched subject: `search -json -in shelf:research "<words>"`. Ordinary search excludes shelves. Before storing an external finding, search there first and use `add -shelf research -source tool -- "<finding>. Source: <document, version or date>."`. Store the source's claim and limits, mark inference, and verify dates or versions before relying on old findings.
- When maintenance hints say a dream is due, use the memcue-dream Skill at a natural pause. The working model answers `dream -prepare` and applies its answer with `dream -apply FILE`; the launcher starts no background model. If prepare reports "no dream yet on this machine", use `dream -prepare -all` or `dream -prepare -since DATE`.
- If memory fails, report the bounded diagnostic and continue unrelated work. Do not claim a failed or timed-out write succeeded; inspect persisted state before retrying. Never replay an unknown mutation automatically.

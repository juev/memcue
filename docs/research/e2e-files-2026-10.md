# memcue against the old file memory, end to end, October 2026

Status: **measured 2026-10-23; memcue stays, its edge over file memory is not proven.** The question was whether
memcue gives the agent more than the file memory it replaced on 2026-10-19, with the same knowledge behind both. On
40 real prompts memcue scores 0.97 of 2 against 0.88 for files and 0.82 with no memory, costs a quarter less than
files and states fewer wrong facts, but the confidence interval of memcue against files crosses zero.

## Modes

Every run is one `claude -p --model opus` in plan mode on a clone of the prompt's repository. The modes differ only in
memory:

- **none**: the memcue hook is silenced (`MEMCUE_BIN=/usr/bin/true`) and the built-in memory is off.
- **files**: the scheme of 2026-06 … 2026-10-19. The built-in memory is on, the project's memory directory is a symlink
  to `memory/<tier>/`, and the old `memory-sync.sh` hook injects `_global/MEMORY.md` at session start. The memcue
  hook is silenced.
- **memcue**: the plugin hook (recall and the session-start card) over a copy of the base, built-in memory off.

Extraction is off in every mode (`MEMCUE_EXTRACT=0`), and every mode gets a throwaway `MEMCUE_FACTS` and
`MEMCUE_STATE_DIR`.

## Same knowledge in both memory modes

- **Snapshot at the prompt's time.** A copy of the live base loses every fact version created after the prompt, and
  its index is emptied so memcue rebuilds it on open. Without this the answer leaks into memory: in the recall replay
  of the same days, 38 of 68 useful facts were created after the prompt.
- **The same snapshot laid out as notes**, without a model. A fact whose origin names its source note
  (`(_global/x.md)`) goes back into that note, with the note's frontmatter and index line from the archive
  `~/.claude/archive/memory-2026-10-19`. A note with no active fact left drops out of the index. A fact extracted from a
  session goes to `<tier>/extracted_<kind>.md`. The tier is `_global` for scope `global`, `host:*` and `service:*`,
  the last path segment for `repo:X`.

## Prompts

- **Source.** Real Mac prompts from `recall.log`: 122 prompts of 21–23.10, of which a blind Opus labeller marked 70
  as needing memory; plus 112 prompts of 19.10 13:00 – 21.10.
- **Filter.** Opus, blind: the prompt is understandable without the earlier conversation. 27 and 15 passed. One was
  dropped because it referred to an image, one because its reference answer had under 300 characters of text.
- **Result.** 40 prompts: 12 in the `~/.claude` config, 8 in memcue, 14 in seven other repositories, 6 in a work repository
  (prompt texts are not published).
- **Reference.** The whole assistant text of the prompt's turn in the real session; a turn longer than 3,500
  characters is cut to its first 1,000 and last 2,500.

## Isolation

- **Repository as of the prompt.** `git clone --shared --no-checkout`, checkout of the last commit before the prompt,
  then every branch moved back to its last commit before the prompt, newer tags deleted and the reflog expired.
- **Read only.** Tools `Read,Grep,Glob,Bash`, `--strict-mcp-config`, a deny list in `--disallowedTools`, and shims on
  `PATH` that fail `ssh`, `glab`, `gh`, `curl`, `memcue`, `claude`, mutating `git` subcommands and the like.
- **The live base.** No fact with a run's origin reached it. The 32 facts it gained during the run came from the
  measuring session's own compaction.

## Grading

One Opus call per prompt with the prompt, the reference and all six answers under shuffled letters, no mode shown.
Each answer gets a score (2 correct and useful, 1 partly, 0 wrong or empty) and three flags: `wrong` (states
something false about the environment, decisions or history), `asks` (asks for what the reference knew at once),
`past` (relies on knowledge of past sessions not in the repository). Two passes with different letter orders; the
score is their mean, a flag counts only when both passes raise it.

## Results

240 runs (40 prompts × 3 modes × 2 repetitions), none failed.

| mode | score | 2s | 0s | wrong | asks | past | turns | tools | cost | median time |
|---|---|---|---|---|---|---|---|---|---|---|
| none | 0.82 | 15 | 28 | 23 | 46 | 4 | 9.3 | 8.3 | $30.19 | 41 s |
| files | 0.88 | 19 | 26 | 29 | 43 | 20 | 9.4 | 8.4 | $42.19 | 44 s |
| memcue | **0.97** | 21 | 21 | **22** | 43 | 22 | 9.0 | 7.9 | $32.07 | 42 s |

memcue served 1.4 facts per prompt on average.

Pairwise by prompt, each side the mean of its two repetitions, with a 95 % bootstrap interval of the mean
difference (5,000 resamples):

| pair | wins / ties / losses | mean diff | 95 % interval |
|---|---|---|---|
| memcue vs files | 15 / 13 / 12 | +0.09 | [−0.11, +0.30] |
| memcue vs none | 14 / 21 / 5 | +0.15 | [−0.02, +0.32] |
| files vs none | 13 / 19 / 8 | +0.06 | [−0.12, +0.23] |

Noise:

- **Grader against itself.** The same score in 219 of 240 answers, no 0↔2 flip; `wrong` raised by both passes in 74
  of the 91 answers either pass flagged.
- **Repetition against repetition.** The two runs of one mode differ on 7 of 40 prompts with no memory, 11 with
  memcue and 21 with files.

## What it means

1. **Both memories reach the agent.** The `past` flag is raised on 20–22 answers with memory against 4 without.
2. **memcue is not worse than files and probably a little better**, but +0.09 is inside the noise of 40 prompts.
   Confirming a difference of this size would take roughly four times as many prompts.
3. **Files cost a third more**: $42 against $32 for the same prompts. The injected `MEMORY.md` index goes into every
   session whole; memcue sends a fact or two.
4. **Files state more wrong facts**: 29 against 22 and 23. Hypothesis, not checked: whole stale notes mislead more
   than single dated facts.
5. **Files are the least stable mode**: 21 of 40 prompts change score between repetitions. Hypothesis, not checked:
   whether the agent opens the notes at all varies from run to run.
6. **Memory against no memory** is borderline for memcue (+0.15, interval [−0.02, +0.32]) and indistinguishable for
   files.

The write side is not measured: whether an agent keeps notes as fully as extraction does is outside this replay.

## The first run, discarded

A first pass of 246 runs on 41 prompts gave none 1.01, files 0.85, memcue 0.95 and was thrown away for two defects:
the clones carried branches and tags from days after the prompt (a prompt about a release could read the release
tag), and 13 of 41 references were nearly empty because the reference was the first 1,500 characters of a turn that
spent them on tool calls. The second run fixed both (branch trimming, full references) and added the second grading
pass.

## Reproduce

Scripts are in [scripts/e2e](scripts/e2e). They expect `prompts-all.json` (prompt, time, cwd, reference) and
`ids-v2.json` next to them and a copy of the live base as `live.db`.

```bash
python3 docs/research/scripts/e2e/refs.py                      # full references, ids-v2.json
python3 docs/research/scripts/e2e/run.py all --ids ids-v2.json --reps 2 --jobs 4
python3 docs/research/scripts/e2e/grade.py run 1
python3 docs/research/scripts/e2e/grade.py run 2
python3 docs/research/scripts/e2e/grade.py report
```

`memory-sync.sh` is the old hook from `~/.claude` (`git show 51edad0^:hooks/memory-sync.sh`) with two overrides
added, `MEMSYNC_STORE` and `MEMSYNC_TIER`, so the run can point it at the snapshot. Cost: about $104 of runs and
two grading passes.

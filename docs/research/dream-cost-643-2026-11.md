# What the dream costs, by task, November 2026 (#643)

Status: **measured 2026-11-06 on a replay of one day of the author's Mac base, 7 passes, 35 calls, $12.77.**
**A third of what a dream call costs is context that `claude -p` loads and the dream never uses.**

The question of #643: which dream tasks cost what, before anyone tunes the schedule or drops a task. The pass record
had only totals, so this change adds a line per model call to `dream.log` (`calls`: task, work given, changes
proposed, tokens, cost, time) and measures one day with it.

In short:

- **Every call carries about 42,500 input tokens that are not the packet.** A `claude -p` call with memcue's flags and
  the prompt "Say ok." reads 43,428 input tokens. With no MCP servers it reads 10,900, and with no setting sources 922.
  `--tools ""` turns the tools off but leaves about 32,500 tokens of MCP server context in the prompt; the user's
  `CLAUDE.md` and rules bring most of the rest. The calls of a pass start at once, so they do not share a warm cache:
  the fitted fixed cost of a call is $0.09–0.23, and 35 calls paid about $4.8 of the $12.77 for it.
- **Translation is the largest task: $4.65 of $12.77 (36%)**, $0.012 a fact beyond its fixed cost, and most of the
  output tokens.
- **The merge sweep costs a quarter.** Review calls that held only swept groups cost $3.15 for 233 groups. The 4 passes
  with no fresh fact applied 13 actions (6 duplicates retired, 5 corrections, 2 outdated facts retired). Whether those
  were worth $2.83 needs the recall comparison this run did not make.
- **The agent writes little of the new work.** Of the 88 facts sessions wrote in the window, 3 are `agent`, 55 `tool`,
  29 `user` and 1 `user_confirmed`. Over the live log since 26 October, dream work falls on each source about in
  proportion to its share of the base (agent facts: 56% of the base, 43% of the splits, 50% of the duplicates).
  The link "the agent writes too much, so the dream is expensive" (#638) does not hold for what is written now.

## Method

- **Base**: the author's text history as of 2026-11-05 09:27 UTC, from its own git history, right after the dream of
  that morning; the dream state marked every fact of it seen. On top: the first version of each of the 88 facts that
  sessions added from 09:30 UTC to 2026-11-06 12:10 UTC. The 90 facts the live dream split off in that window were left
  out: a part has no keywords and is written within 2 s of the retired version of its fact.
- **Run**: `dream -run -all` of this branch on Opus 5.5 through `claude -p`, as the background dream runs, with
  `MEMCUE_FACTS` and `MEMCUE_STATE_DIR` on the copy. It ran until nothing was left: 7 passes.
- **Reference**: the live dream did the same window in 5 background passes for $17.68 (it also had the facts pulled
  from other machines and edited by sessions, which the replay lacks).
- **Fixed cost**: a least-squares fit of cost = fixed + per unit × units for each task; the probe calls above, run
  from the repository on the same machine, $0.45.
- **Sources**: the `source` of a fact's first version; a fact without one counts as `agent`, as the store reads it.

Fact texts, the copy and the scripts stay out of the repository.

## Recommendation

1. **Load no MCP servers in memcue's `claude -p` calls** (`--strict-mcp-config` with an empty config). The tools are
   off already, so the answer should not change; the input of a call drops by about 32,500 tokens. Keep the setting
   sources: they carry the user's thinking and effort settings, which a dream answer depends on, so dropping
   them would change more than cost. **Done in #660**: the first pass of the replay again, from the same state, read
   296,072 input tokens instead of 517,421 and cost $4.18 instead of $5.19, with the same work given (88 fresh facts,
   86 groups, 10 calls, 114 translations). It applied 16 splits and 3 actions against 19 and 5; one run of each side
   cannot tell that from the model's own variation.
2. **Keep the schedule as it is until the recall comparison is made.** The sweep is the only task that spends without
   new facts; the other tasks do what new facts need. Capping the sweep (once a day rather than once a pass) is the
   first candidate once its value is known.
3. **A budget, when one is wanted, counts calls, not dollars**: an endpoint reports no cost, and a call has a known
   fixed price on `claude -p`. When the budget of a day is spent, the dream defers the sweep first, then the scope
   check, and keeps the fresh facts and translations owed, so the next day's dream takes them; the session start is
   not held, since the dream runs in the background. Not built: it waits for the decision on 1 and 2.

## Limits

- One day of one person's base, one run; a repeat would show how much the cost of a pass varies.
- `-run -all` packs the day into 7 passes; the background dream made 5, and every pass sweeps 200 facts, so the sweep's
  share differs with the number of passes.
- The value of each task (recall with and without it) is not measured here; the ablations of #643 item 2 move to #661
  by the user's decision; [dream-ablations-661-2026-11.md](dream-ablations-661-2026-11.md) found no task, and not the
  whole dream, making a measurable difference over one day.
- Claude Code only. The DeepSeek endpoint reports tokens without a price.

# The session card trimmed to behaviour, on real prompts, November 2026 (#606)

Status: **measured 2026-11-03 on 40 real prompts, two arms, two repetitions each.** **The trimmed card scores lower: keep the card as it is.**

The question of #606: should the session card carry only the user's standing rules of behaviour, and hand the rest to
the moment of action (a command, a file) and to search? The exploratory replay of
[card-replay-606](card-replay-606-2026-11.md) left it open: 13 ties and 11 unknown of 24 pairs, a reduced tool set and
labels from another vendor's model. This run replays real prompts with the whole agent, as the e2e runs of
[pull-2026-10](pull-2026-10.md) did, and grades blind with Opus.

In short:

- **Trim scores 1.16 of 2, the current card 1.26.** By prompt, trim wins 5, ties 22 and loses 13; the mean difference
  is −0.09, 95% interval [−0.20, +0.01]. The interval touches zero, but every count points the same way: trim has 23
  answers scored 2 against 34, and its two repetitions disagree on 14 prompts against 7.
- **What trim saves is small.** The card goes from 61 facts to 37; the whole run costs $30.76 against $32.87 (6%), and
  the median time and the turns barely move.
- **The agent did not make up for it by searching.** Trim searched in 65 of 80 runs, 2.3 times a run; the current card
  in 69 runs, 3.0 times.
- **The losses are not one class.** The facts trim removed look alike in the prompts it lost and in those it won: about
  12 global facts about one repository, 3–4 knowledge facts and 3 command facts a prompt.
- Recommendation: no change to the card's selection, and no implementation issue for a behaviour-only card. The facts
  that should leave the card are the global ones about one repository; #607 already moves them to their repository,
  where they stay on that repository's card.

## Arms

Both arms are one `claude -p --model opus` in plan mode on a clone of the prompt's repository as of the prompt, with the
memcue plugin, the user's own settings and hooks, and a throwaway copy of the fact base as of the prompt. The agent can
search the base itself (`memcue search`, the production mode since #361). The arms differ only in the card:

- **current**: the card of `main` (957b7a3): global rules, the global decisions the user stated, the rules and
  decisions of the session's repository whatever their source, in the three SessionStart parts of #495.
- **trim**: the same card with only the facts of the keep list: the facts Opus labelled `behaviour`, and the rules and
  decisions of a repository the user stated (`source` user or user_confirmed). Question 1 of #606. A research-only
  patch ([card-keep.patch](scripts/card606e2e/card-keep.patch), `MEMCUE_CARD_KEEP`) filters the facts by id before the
  card is rendered; it is not in `main`.

Everything left out of the trimmed card stays in the base, and the agent can find it by search.

## Prompts

- **Source.** Every prompt the person typed in an interactive Claude Code session (not `claude -p`) on the Mac from
  2026-10-26 to 2026-11-02, whose working directory still exists and is a git repository or the Claude config
  directory, with 20–2,000 characters and a turn of at least 300 characters of assistant text: 467 candidates in 18
  repositories ([candidates.py](scripts/card606e2e/candidates.py)).
- **Filter.** Opus through `claude -p`, blind to the session and the answer, labelled each prompt: can a fresh session
  act on it, is it a task rather than a go-ahead, may a good answer depend on what the person decided or set up in
  earlier sessions ([filter.py](scripts/card606e2e/filter.py), $1.60). 161 were standalone tasks, 95 of them with
  memory.
- **Sample.** 40 of the 95, round-robin over the repositories with at most eight a repository: 18 repositories, 32
  prompts in the author's own repositories, 5 in work repositories, 3 in the Claude config directory. One prompt asked
  before its repository's first commit was replaced by another from the same pool.
- **Reference.** The whole assistant text of the prompt's turn in the real session, its first 1,000 and last 2,500
  characters when longer (median 1,939 characters). The real session had every tool and the state of that day; a
  reference can be better than any plan-mode answer can be.

Prompt texts, references, answers and labels stay out of the repository.

## Isolation

A replay of a past prompt must not see what was learnt after it. The first attempts of this run did, and were thrown
away (about $13 of runs):

- The clone was `git clone --shared` with its branches cut back to the prompt, as in the e2e runs of October. Through
  the alternates it still held every later object, and an agent named the commits of this experiment's own branch.
  The clone is now an empty repository that fetches only the history of the prompt's commit and of the default
  branch's last commit before it; the newest object in a test clone was older than its prompt.
- The shims printed "blocked in the e2e run (read-only replay)", lived under a path naming the experiment, and the
  clone kept other branches' names: agents said they were in a replay of #606. The shims, the binary and the keep
  list now live under a neutral path with neutral messages, and the clone keeps only its default branch.
- `git ls-remote` reached GitHub and showed later branches; the git shim refuses it and any argument naming the live
  repositories, base or data.
- A binary of a pseudo-version made the plugin warn at every session start that the binary was older than the
  plugin; the binary now carries the plugin's version.
- The file tools may not read the live repositories, the live base or the data of the run. Bash still can; each run
  records the commands that named those paths. 35 of 160 runs tried (18 current, 17 trim), the shims refused nearly
  all of it, and 2 current runs got some output back.
- The binary was copied over itself at every run while other runs executed it, and macOS killed it: 22 sessions, 11
  an arm, started without memory. They were run again with the binary installed once, and their prompts graded again.

A relabel keeps the creation time of a fact (store.Relabel), so a scope set after the prompt can show through in the
snapshot. Both arms share every leak that is left.

## Results

160 runs (40 prompts × 2 arms × 2 repetitions), none failed, $63.63; the thrown-away attempts and the 22 runs again
add about $22. Graded by [grade606.py](scripts/card606e2e/grade606.py): one Opus call a prompt reads the prompt, the
reference and the four answers under letters in a per-pass order; two passes, $12.31 and $5.67 for the prompts graded
again. A flag counts when both passes raise it; a score is the mean of the two.

## Questions of #606

1. **Behaviour plus the stated rules and decisions of the repository: better, the same or worse?** Worse in direction:
   −0.09 [−0.20, +0.01], 13 prompts worse and 5 better, 11 fewer answers scored 2, and half again as unstable between
   repetitions. Not a gain that would pay for the change.
2. **How should a fact join the card?** With trimming not paying off, no admission mechanism is needed now. If the
   question comes back: Opus labelled the 351 card facts by channel for $1.70, so a label a dream proposes is cheap;
   the behaviour class is small (40 of 351 facts, 39% of what the cards carry because every card carries them).
3. **Should the repository decisions the agent wrote leave the card?** This run does not isolate them: trim removed them
   together with the global facts about one repository and the knowledge facts. They are 143 of the 351 facts and 11%
   of what the cards carried (259 of 2,429). Taking them off would need an arm of its own; given the result above, the
   default is to keep them.
4. **Which command and file facts does the program hook already serve?** None of the 21 on the cards. All of them are
   rules or decisions; the program hook of the author's Claude Code config looks for pitfalls and environment facts
   only, and #598 recommends no file hook for now. Taking them off the card would leave them to search alone.

## Limits

- One run of 40 prompts. The interval touches zero; the conclusion is "trim does not help", not "trim surely hurts".
- The prompts are from eight days of one person's work, and 95 of 161 candidates were judged to need memory before
  the sample was drawn from them.
- Plan mode, without network and without writes, answers what the agent would do, not whether the task got done. The
  reference comes from a session that had every tool and that day's state.
- One labeller (Opus) for the channels; the keep list follows its labels.
- The snapshot can show a scope set after the prompt (a relabel keeps the creation time), and 2 current runs read
  some live state through Bash.
- Claude Code only. Hermes and DSH build a smaller card (#487) and were not run.

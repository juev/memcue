# Выпуск 0.22.0 и переход на текстовую историю, октябрь 2026

Статус: **замеры для [#555](https://github.com/juev/memcue/issues/555), 2026-10-28; код продукта не менялся.**

Коротко:

- 0.22.0 установлен на Mac (darwin/arm64), loffe (linux/amd64) и в Hermes на loffe; база Hermes тоже переведена на
  текстовую историю (см. «База Hermes»). На Mac и loffe обновлён плагин
  Claude Code, обёртка плагина вызывает бинарник 0.22.0. Тесты провайдера Hermes в контейнере: 77 из 77.
- Синхронизируемая база `~/.claude/memory` переведена на текстовую историю на Mac: `memcue migrate -text` за 1.3 с
  записал 4712 фактов и 19 015 версий, ровно столько же ID и строк, сколько в исходном SQLite. loffe получил текст
  через `git pull`, кеш собрался при первом открытии.
- Содержимое не изменилось: вывод `memcue facts` до и после перехода совпадает байт в байт на обеих машинах
  (sha256 `439d903e…`, 3676 активных фактов). Ответы поиска на 30 фиксированных запросов совпали 30 из 30 на каждой
  машине.
- Скорость повседневных команд осталась прежней. Исключения: поиск стал медленнее на 2–4 мс, а первое открытие без
  кеша теперь собирает его из текста за 1.7 с на Mac и 3.7 с на loffe.
- Запись факта после перехода добавляет в git один файл на 678 байт. До перехода на её месте пересохранялся бы весь
  `facts.db` на 37 МБ.

## Метод

Скрипт замера (не в репозитории, одноразовый) на каждой машине делает одно и то же:

1. `memcue facts` в файл: содержимое и его sha256.
2. 30 фиксированных запросов (русские и английские, по хостам, репозиториям и правилам) через
   `memcue search -json -n 5`, три круга; ID ответов записываются с первого круга, время — со всех.
3. `memcue session-start -part 1..3`, по 10 запусков каждой части.
4. Копия базы во временный каталог со своим `MEMCUE_STATE_DIR`: первое открытие копии (cold-open), затем 10 циклов
   `add` → `correct` → `retire`. Живая база не пишется.

«До» снято на 0.21.2 с `facts.db`, «после» — на 0.22.0 с текстовой историей. Время — wall clock процесса, медиана и
p90. Все команды запускаются со `stdin=/dev/null`: `session-start` читает JSON hook'а со stdin до EOF и с открытым
stdin висит (так ведут себя 0.21.2 и 0.22.0, это не регрессия).

Разбор:

- **`facts` на loffe 134 → 319 мс** — одиночный замер. Повтор по семь запусков дал 121 мс против 115 мс:
  разница в пределах шума, регрессии нет.
- **Поиск медленнее на 2–4 мс** (13–25 %) на обеих машинах, повтор на loffe это подтверждает. Абсолютная прибавка
  мала по сравнению с ходом модели. Почему так, не выяснялось. Гипотеза, не проверено: при каждом открытии memcue
  сверяет каталоги текста с отметками в кеше.
- **cold-open** до перехода — открытие готового SQLite. После перехода — сборка кеша из 4712 файлов. Платится один
  раз на машину или после потери кеша. На Mac 1.66 с согласуется с 1.6 с из #552.
- `correct` на loffe 234 → 262 мс, p90 290 → 277 мс; остальные записи без изменений. Это шум, разницы нет.

## Корректность

- Сравнение до и после перехода через `memcue facts` совпало байт в байт на Mac и на loffe. Число ID и версий в
  тексте совпадает с исходным SQLite: 4712 и 19 015.
- Поиск: 30 из 30 одинаковых ответов на каждой машине. Первое сравнение на Mac дало 16 из 30, но «до» там
  снималось из репозитория memcue, а «после» — из `~/.claude`. Поиск в репозитории ограничен им, хостом и
  глобальными фактами, поэтому ответы разошлись из-за каталога, а не из-за базы. Повтор из того же каталога дал
  30 из 30.
- Живая база после перехода: `memcue add` записал факт, тот сразу нашёлся поиском, `reindex -dry-run` видит 3677
  активных строк индекса (3676 + новый факт). Все три части карточки сессии собираются, и ни одна не упоминает `migrate -text`.

## База Hermes

База Hermes (`/opt/data/memcue/facts.db` в контейнере) не лежит в git, её перевели следом тем же `migrate -text`.
Порядок: остановлен gateway, сделан бэкап `facts.db.pre-text.bak`, снят замер «до», выполнен переход, снят замер
«после», gateway запущен снова. Перед этим переход прогнали на копии. На базе вне git `migrate -text` пишет
`... is not in a git repository: nothing to set up for sync` и завершается с кодом 0.

- 983 факта, 2748 версий; `memcue facts` до и после совпадает байт в байт (412 активных фактов), поиск 30 из 30.
- Провайдер после перезапуска открыл текст: маркер `base` сменился на `/opt/data/memcue/facts`. Разовая сессия
  `hermes -z` нашла ответ через `memcue_search`.
- Замер шёл через `memcue-real` без обёртки, чтобы не писать в `search.log` строки, которые попали бы в замеры #478.

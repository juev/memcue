# Releasing 0.22.0 and moving to the text history, October 2026

Status: **measurements for [#555](https://github.com/juev/memcue/issues/555), 2026-10-28; no product code changed.**

In short:

- 0.22.0 is installed on the Mac (darwin/arm64), on loffe (linux/amd64) and in Hermes on loffe; the Hermes base moved
  to the text history too (see "The Hermes base"). The Claude Code plugin is updated on the Mac and loffe, and its
  wrapper runs the 0.22.0 binary. The Hermes provider tests in the container: 77 of 77.
- The synced base `~/.claude/memory` moved to the text history on the Mac: `memcue migrate -text` wrote 4712 facts and
  19,015 versions in 1.3 s, exactly the IDs and rows of the original SQLite. loffe got the text through `git pull`,
  and its cache was built at the first open.
- The content did not change: the output of `memcue facts` before and after the move is byte-identical on both
  machines (sha256 `439d903e…`, 3676 active facts). The search answers to 30 fixed queries matched 30 of 30 on each
  machine.
- Everyday commands are as fast as before. Two exceptions: search got 2–4 ms slower, and the first open without a
  cache now builds it from the text in 1.7 s on the Mac and 3.7 s on loffe.
- After the move, writing a fact adds one 678-byte file to git. Before it, the whole 37 MB `facts.db` would have been
  stored again.

## Method

A one-off measurement script (not in the repository) does the same on each machine:

1. `memcue facts` into a file: the content and its sha256.
2. 30 fixed queries (Russian and English, about hosts, repositories and rules) through `memcue search -json -n 5`,
   three rounds; the answer IDs are taken from the first round, the times from all.
3. `memcue session-start -part 1..3`, 10 runs of each part.
4. A copy of the base in a temporary directory with its own `MEMCUE_STATE_DIR`: the first open of the copy
   (cold-open), then 10 cycles of `add` → `correct` → `retire`. The live base is not written.

"Before" was taken on 0.21.2 with `facts.db`, "after" on 0.22.0 with the text history. Times are the process's wall
clock, median and p90. Every command runs with `stdin=/dev/null`: `session-start` reads the hook's JSON from stdin
until EOF and hangs with an open stdin (0.21.2 and 0.22.0 alike; not a regression).

## Results

Median, ms (before → after):

| command | Mac | loffe |
|---|---|---|
| `facts` (1 run) | 273.6 → 77.5 | 133.9 → 318.7 |
| `facts` (7 runs, repeat) | — | 121.1 → 114.9 |
| `search` (90 runs) | 12.2 → 13.9 | 13.4 → 17.1 |
| `search` (15 runs of one query, repeat) | — | 16.6 → 20.7 |
| `session-start -part 1` | 59.6 → 55.1 | 315.0 → 292.6 |
| `session-start -part 2` | 59.4 → 56.6 | 302.1 → 296.8 |
| `session-start -part 3` | 59.0 → 54.6 | 301.3 → 296.4 |
| cold-open of the copy | 67.0 → 1658.8 | 126.1 → 3669.5 |
| `add` | 124.7 → 118.6 | 240.8 → 237.6 |
| `correct` | 125.3 → 129.1 | 234.4 → 262.4 |
| `retire` | 125.2 → 118.6 | 239.7 → 233.9 |

Reading:

- **`facts` on loffe 134 → 319 ms** is a single run. A repeat of seven runs gave 121 ms against 115 ms: within noise,
  no regression.
- **Search is 2–4 ms slower** (13–25%) on both machines; the repeat on loffe confirms it. The absolute cost is small
  next to a model's turn. Why was not established here. Hypothesis, not checked: every open makes memcue compare the
  text directories with the stamps in the cache. ([#557](https://github.com/juev/memcue/issues/557) later traced it
  to the stamp writes; see [text-open-cost-557](text-open-cost-557-2026-10.md).)
- **cold-open** before the move is opening a ready SQLite file; after it, building the cache from 4712 files. It is
  paid once per machine or after a lost cache. 1.66 s on the Mac agrees with the 1.6 s of #552.
- `correct` on loffe 234 → 262 ms, p90 290 → 277 ms; the other writes did not change. Noise, no difference.

## Correctness

- `memcue facts` before and after the move is byte-identical on the Mac and on loffe. The text holds as many IDs and
  versions as the original SQLite: 4712 and 19,015.
- Search: 30 of 30 identical answers on each machine. The first comparison on the Mac gave 16 of 30, but "before"
  was taken from the memcue repository and "after" from `~/.claude`. A search in a repository is limited to it, the
  host and the global facts, so the answers differed because of the directory, not the base. A repeat from the same
  directory gave 30 of 30.
- The live base after the move: `memcue add` wrote a fact, search found it at once, and `reindex -dry-run` sees 3677
  active index rows (3676 plus the new fact). All three parts of the session card build, and none mentions
  `migrate -text`.

## The Hermes base

The Hermes base (`/opt/data/memcue/facts.db` in the container) is not in git; it was moved next, with the same
`migrate -text`. Order: the gateway stopped, a backup `facts.db.pre-text.bak` made, "before" measured, the move run,
"after" measured, the gateway started again. The move was tried on a copy first. On a base outside git
`migrate -text` prints `... is not in a git repository: nothing to set up for sync` and exits 0.

- 983 facts, 2748 versions; `memcue facts` before and after is byte-identical (412 active facts), search 30 of 30.
- After the restart the provider opened the text: its `base` marker changed to `/opt/data/memcue/facts`. A one-shot
  `hermes -z` session found its answer through `memcue_search`.
- The measurement ran `memcue-real` without the wrapper, so as not to write lines into `search.log` that would enter
  the measurements of #478.

Median, ms (before → after):

| command | Hermes |
|---|---|
| `search` (90 runs) | 7.0 → 9.7 |
| `session-start -part 1..3` | 14.5 → 17.2 |
| cold-open of the copy | 16.5 → 541.6 |
| `add` / `correct` / `retire` | 26.9 → 32.7 / 26.6 → 35.5 / 27.0 → 31.3 |

On the small base the cost shows best: about 3 ms on every command and 5–9 ms on writes.
[#557](https://github.com/juev/memcue/issues/557) looks into the cause.
